## Декомпозиция сценариев

### Export API

**Бизнес-логика:** пользователь скачивает закладки для переноса данных в другой сервис.

**Что важно проверить:**

1. **Auth gate** — незалогиненный пользователь не должен получить чужие данные.
2. **Empty state** — новый пользователь без закладок → корректный пустой ответ (не 500).
3. **Format negotiation** — каждый format возвращает правильный MIME-тип.
4. **Content-Disposition** — браузер должен предложить скачать файл, а не открыть в окне.
5. **Error handling** — неизвестный format → понятный 400, не 500 и не пустой ответ.

**Граничные случаи:**
- Пустой список закладок: `[]` (не null, не объект, не 204)
- Неизвестный format (`?format=xml`): 400 с упоминанием "xml" в detail — пользователь понимает что именно не так

### Settings API

**Бизнес-логика:** пользователь управляет настройками AI-анализа — язык LLM, часовой пояс, уведомления.

**Что важно проверить:**

1. **Auth gate** — настройки личные, 401 без токена.
2. **Default values** — новый пользователь получает разумные дефолты (язык, часовой пояс).
3. **Partial update** — PATCH одного поля не сбрасывает другие поля.
4. **Public endpoint** — `GET /defaults` специально открыт без авторизации (нужен для onboarding UI).

## Методология

- **Порядок тестов:** сначала auth gate (самый ранний rejection point), затем happy path, затем edge cases.
- **Тестовая изоляция:** каждый тест работает с отдельным тестовым пользователем через фикстуру `test_user`.
- **Real database:** тесты запускаются против реального PostgreSQL в Docker (не mocks) — проверяется реальное поведение, включая SQL-запросы.
- **Async:** все тесты асинхронные (`pytest-asyncio`), так как FastAPI и httpx работают async.
