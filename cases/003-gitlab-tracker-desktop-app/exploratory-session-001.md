# Exploratory Session 001 — Эталонное поведение GitLab CE

**Чартер:** Исследовать GitLab CE нативно (без трекера), чтобы зафиксировать эталонное поведение — как данные реально выглядят в GitLab до попадания в GitLab Tracker. Основа для Этапа 2: каждое расхождение трекера сравниваем с этим эталоном.

**Тестировщик:** Тина Юмашева
**Дата:** 10–24 августа 2026
**Таймбокс:** несколько сессий суммарно (~3 часа)
**Окружение:** GitLab CE (self-hosted), Chrome, тестовый проект-песочница

---

## Подготовка

Создала тестовый проект-песочницу с полным набором данных:
- Scoped labels: `Статус::К выполнению`, `Статус::В работе`, `Статус::Приёмка`, `Тип::ошибка`, `Тип::функция`
- Kanban-доска с колонками по `Статус::`
- 7 задач с разными параметрами: исполнитель, дедлайн, milestone, Markdown-описание, confidential, вложения, MR
- Milestone: Sprint-1
- Draft MR, привязанный к задаче через `Closes #N`

## 9 наблюдений

### Наблюдение 1 — Drag-and-drop: UI не обновляется без перезагрузки

**Действие:** Перетащила карточку из колонки `Статус::К выполнению` в `Статус::В работе`.

**Произошло:**
- Карточка визуально переехала в новую колонку ✅
- Панель задачи справа показывала старый лейбл — даже после закрытия и повторного открытия ❌
- После F5 — лейбл обновился ✅
- Activity log подтвердил: `added Статус::В работе and removed Статус::К выполнению`

**Вывод:** GitLab обновляет лейбл на сервере **сразу**, но UI показывает устаревшие данные до перезагрузки. Это эталонное поведение.

**Риск для трекера:** Трекер использует оптимистичный UI. Нужно проверить: после drag-and-drop в трекере — лейбл обновляется сразу, после синка (30 сек) или только после ручного обновления?

### Наблюдение 2 — Создание задачи: автооткрытие панели деталей

**Действие:** Создала задачу через кнопку `+` в колонке доски.

**Произошло:** После "Create issue" — панель деталей открылась **автоматически**. Можно было сразу заполнять Assignee, Labels, Dates без отдельного клика.

**Вывод:** GitLab нативно открывает созданную задачу сразу — удобный UX.

**Риск для трекера:** Открывает ли трекер Drawer автоматически после создания задачи?

---

### Наблюдение 3 — Scoped labels: два измерения одновременно

**Действие:** Добавила к задаче два лейбла: `Статус::К выполнению` и `Тип::ошибка`.

**Произошло:** Оба лейбла применились без конфликта. Разные prefix-ы (`Статус::` и `Тип::`) не конфликтуют. Внутри одного scope — допустим только один лейбл.

**Вывод:** Это основа compliance-проверки в трекере — `too_many` violation возникает именно когда у задачи два лейбла с одинаковым prefix-ом.

### Наблюдение 4 — Просроченный дедлайн: минималистичный индикатор

**Действие:** Задача с дедлайном в прошлом.

**Произошло:**
- На карточке доски появилась иконка 📅 с датой, показывающая относительное время просрочки ("Yesterday", "2 days ago")
- Цвет карточки **не изменился** — только иконка
- Никакого явного "Overdue" статуса

**Вывод:** GitLab показывает просрочку минималистично — иконка + относительное время, без цвета.

**Риск для трекера:** Как трекер показывает просрочки? Этот индикатор критичен при работе с 87+ проектами.

### Наблюдение 5 — Confidential issue: визуальное выделение

**Действие:** Создала задачу с галочкой "Turn on confidentiality".

**Произошло:**
- В списке задача появилась **выше** обычных с особой иконкой — визуально отличается
- Кнопка называется `New item`, но открывшееся окно — `New Issue`: несоответствие терминологии (GitLab в переходном периоде, переименовывает "Issues" → "Work Items")

**Риск для трекера:** Показывает ли трекер confidential-задачи? Есть ли индикация?

### Наблюдение 6 — Internal note: видимость и безопасность вложений

**Действие:** Отправила комментарий с PDF-вложением с галочкой "Make this an internal note".

**Произошло:**
- Комментарий появился с жёлтым бейджем `Internal note`
- **GitLab показал предупреждение:** "Uploaded files will be accessible to anyone with the file URL. Use caution."

**Вывод:** Internal note скрыт от гостей в UI, но вложение внутри него доступно **по прямой ссылке без авторизации** — конфиденциальность note не распространяется на файлы.

**Риск для трекера:** Показывает ли трекер internal notes? Отображает ли бейдж?

### Наблюдение 7 — Issue links: тип связи по умолчанию

**Действие:** Связала задачу #3 с задачей #1 через блок `Linked items`.

**Произошло:**
- Тип связи автоматически установился как `Related to` — явного выбора типа (blocks / is blocked by) в интерфейсе Work Items не было
- Связь двунаправленная — в обеих задачах появилась ссылка

**Вывод:** В Work Items интерфейсе тип связи фиксируется как "Related to". В классическом Issues — можно выбрать тип явно.

**Риск для трекера:** Какие типы связей показывает трекер в Drawer?

### Наблюдение 8 — MR: автозаполнение из задачи и магическое слово Closes

**Действие:** Создала MR из задачи #1 через кнопку `Create merge request`.

**GitLab заполнил автоматически:**
- Title: `Draft: Resolve "название задачи"` — с префиксом Draft
- Description: `Closes #1` — при мерже задача закроется автоматически
- Milestone и Labels — унаследованы из задачи

**Вывод:** GitLab связывает MR и задачу двусторонне. `Closes #N` — стандарт индустрии для автозакрытия.

**Риск для трекера:** Показывает ли трекер список связанных MR в Drawer? Отображается ли статус MR (Draft / Open / Merged)?

### Наблюдение 9 — Закрытие задачи: два независимых состояния

**Действие:** Закрыла задачу #1 через меню → "Close Issue".

**Произошло:**
- Карточка **мгновенно** переместилась в системную колонку `Closed` — без перезагрузки
- Лейбл `Статус::К выполнению` **остался на карточке** в Closed — не удалился и не сменился

**Вывод:** GitLab разделяет два независимых состояния:
1. **Lifecycle state** (Open / Closed) → системная колонка `Closed`
2. **Workflow state** (`Статус::` лейбл) → управляется drag-and-drop, не меняется автоматически при закрытии

Закрытая задача может сохранять лейбл `Статус::К выполнению` — это не баг, а архитектура.

**Риск для трекера:** Трекер синхронизирует `state` (closed/opened) и `Статус::` по отдельным полям API. Нужно проверить: если задача закрыта, но лейбл `Статус::К выполнению` — что показывает трекер?
